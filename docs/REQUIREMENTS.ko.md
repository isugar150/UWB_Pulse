# SmartTag UWB Monitor — Android 앱 개발

당신은 Android Native, Kotlin, UWB(Ultra-Wideband), Bluetooth GATT, Samsung SmartTag 프로토콜 및 Android 백그라운드 서비스에 전문성을 갖춘 시니어 Android 엔지니어입니다.

## 1. 프로젝트 목표

삼성 갤럭시 스마트태그2(SmartTag2)와 스마트폰 사이의 **실시간 UWB 거리값을 측정하고, 설정한 임계거리를 벗어나면 자동화 이벤트를 실행하는 Android 앱**을 개발합니다.

궁극적인 사용 사례는 차량 내부에 스마트태그2를 배치하고, 스마트폰을 가진 사용자가 차량에서 일정 거리 이상 멀어졌을 때 자동화를 실행하는 것입니다.

차량 제어 자체는 이번 프로젝트의 범위가 아닙니다.

### 개발 환경

- 대상 스마트폰: Samsung Galaxy Z Fold8
- OS: One UI 9 / Android 버전은 실제 기기에서 확인
- 대상 태그: Samsung Galaxy SmartTag2
- 개발 언어: Kotlin
- UI: Jetpack Compose + Material 3
- 빌드: Gradle Kotlin DSL
- 아키텍처: MVVM + Clean Architecture
- Android SDK 및 라이브러리: 개발 시점의 최신 안정 버전
- 배포: APK 직접 설치
- 루팅 및 별도 하드웨어 사용 금지

## 2. 핵심 기능

### A. 스마트태그 선택

앱을 실행하면 삼성 계정에 등록된 스마트태그2 목록을 조회하고 선택할 수 있도록 구현합니다.

- 태그 이름 및 연결 상태 표시
- UWB 지원 여부 확인
- 선택한 태그를 기본 장치로 저장
- 재실행 시 자동 복원
- 가능하면 여러 태그 지원을 고려한 구조 설계

삼성 공식 API가 제공되지 않는다면 관련 오픈소스와 통신 프로토콜을 분석하여 가능한 방법을 구현합니다.

기존 Samsung Find / SmartThings와 태그 등록 정보를 공유할 수 있는지 검증합니다. 기존 등록을 삭제하거나 초기화하지 않고 사용할 수 있어야 합니다.

### B. UWB 실시간 거리 측정

선택한 스마트태그2와 UWB Ranging Session을 생성합니다.

- 스마트폰과 태그 사이 실제 거리(m) 표시
- 측정값 실시간 업데이트
- UWB 연결 상태 표시
- 연결 실패 및 재연결 처리
- 측정 불확실성 및 신호 품질 표시(지원 시)
- Android UWB API 우선 활용

**BLE RSSI를 거리 측정값으로 대체하지 마세요.**

BLE는 태그 탐색 및 UWB 세션 설정을 위한 OOB 통신 목적으로만 허용합니다.

UWB 측정값을 확보할 수 없다면 임의의 거리값을 생성하지 말고 명확한 오류를 표시합니다.

### C. 거리 임계값 설정

메인 화면에 거리 임계값 슬라이더를 구현합니다.

- 설정 범위: 1~15m
- 조정 단위: 0.5m
- 기본값: 5m
- 현재 거리와 설정 거리 동시 표시
- 설정값 DataStore에 영구 저장
- 실시간 임계값 변경 지원

단순한 거리값 변동 때문에 자동화가 반복 실행되지 않도록 히스테리시스 및 디바운싱 로직을 적용합니다.

예시:

- 설정 거리: 5m
- 실제 UWB 거리 5m 초과
- 3초 이상 지속되는 경우 이탈 이벤트 발생
- 다시 4m 이내로 진입하면 상태 초기화
- 이탈 상태에서 이벤트 중복 실행 방지

거리 측정이 중단되거나 태그 연결이 끊어졌다는 이유만으로 이탈 이벤트를 발생시키지 않습니다.

### D. 백그라운드 UWB 모니터링

**이 프로젝트에서 가장 중요한 기능입니다.**

사용자가 다른 앱을 사용하거나 화면을 꺼도 스마트태그2와의 UWB 거리 측정을 유지하는 것이 목표입니다.

다음 기능을 구현하고 실제 기기에서 검증합니다.

- Foreground Service 기반 모니터링
- 화면 OFF 및 잠금화면 상태 지원
- 앱이 백그라운드로 이동해도 거리 감지
- Android 배터리 최적화 정책 대응
- 모니터링 상태를 지속 알림으로 표시
- OS가 허용하는 범위에서 연결 자동 복구
- 사용자에 의한 모니터링 ON/OFF
- UWB 사용으로 인한 배터리 소비 최소화

AndroidX Core UWB와 Android 최신 Ranging API를 비교하여 적합한 구현을 선택합니다.

**중요: Android의 백그라운드 UWB 제약을 우회할 수 있다고 가정하지 마세요.**

실제 기기에서 거리 측정 결과를 백그라운드로 수신할 수 있는지 우선 검증합니다.

불가능한 경우 기술적 원인과 제한사항을 기록하고, 화면 ON 상태 등 가능한 동작 범위를 명확히 구분합니다.

### E. 루틴 및 자동화 연동

임계거리 이탈 이벤트를 외부 자동화 시스템에서 활용할 수 있도록 구현합니다.

우선순위:

1. 삼성 갤럭시 모드 및 루틴과 공식적으로 연동할 수 있는 방법 조사 및 구현
2. 직접 연동이 불가능하면 Tasker 플러그인 이벤트 지원
3. Android 시스템 알림 발행
4. 선택적으로 HTTP Webhook 지원

외부 자동화 시스템은 다음 이벤트를 활용할 수 있어야 합니다.

- `TAG_DISTANCE_EXCEEDED`
- `TAG_RETURNED`
- `TAG_DISCONNECTED`
- `UWB_MONITORING_ERROR`

이벤트 데이터 예시:

```json
{
  "event": "TAG_DISTANCE_EXCEEDED",
  "tagId": "selected-tag",
  "distanceMeters": 5.8,
  "thresholdMeters": 5.0,
  "timestamp": "2026-11-07T10:30:00+09:00"
}
```

알림은 개별적으로 활성화하거나 비활성화할 수 있도록 구현합니다.

Webhook은 HTTPS를 기본으로 하고 인증 토큰, 타임아웃, 재시도 정책을 적용합니다. 태그 식별자 등 민감한 데이터는 필요한 경우에만 전송합니다.

https://github.com/KieronQuinn/uTag

특히 다음을 분석합니다.

- 스마트태그2 통신 프로토콜

- UWB Ranging 결과 수신
- Bluetooth GATT 통신
- SmartThings 인증 및 암호화 의존성
- AndroidX UWB 활용 방식
- One UI 버전 검사 및 호환성 문제

사용 중인 One UI 9에서 uTag가 호환되지 않는다는 오류가 발생했으므로 원인을 조사하고, 정상적인 독립 앱 구현이 가능한지 검토합니다.

기존 코드의 라이선스(GPL 등)를 준수하고, 필요한 경우 오픈소스 라이선스에 맞춰 프로젝트를 구성합니다.

https://developer.android.com/develop/connectivity/uwb

https://developer.android.com/develop/connectivity/ranging

Android 공식 API와 샘플을 우선 사용하고, 삼성 비공개 API가 필수적인 경우 별도로 표시합니다.

관련 라이브러리와 Android 버전별 제약은 최신 문서를 확인하여 판단합니다.

## 5. 기술적 제약 및 개발 원칙

- 실제 UWB 거리 측정을 반드시 사용합니다.
- RSSI 기반 추정 거리로 요구사항을 대체하지 않습니다.
- 스마트태그2의 펌웨어를 수정하지 않습니다.
- 차량 배선이나 외부 UWB 하드웨어를 추가하지 않습니다.
- 루팅 및 시스템 무결성 훼손을 요구하지 않습니다.
- 기존 Samsung Find 및 SmartThings 기능을 최대한 유지합니다.
- 삼성 계정 인증정보를 평문으로 저장하지 않습니다.
- 필요한 최소 권한만 요청합니다.
- API 토큰과 로그에 민감정보가 노출되지 않도록 합니다.
- 백그라운드 동작을 검증하지 않은 상태에서 지원한다고 주장하지 않습니다.
- 불가능한 기능은 가짜 구현이나 Mock으로 대체하지 않습니다.
- 테스트용 Mock은 명시적으로 분리합니다.

## 6. 개발 진행 방식

기능을 무조건 전부 구현하기보다 **가장 위험도가 높은 기술부터 검증**합니다.

### Phase 1 — UWB 기술 검증

먼저 실제 갤럭시 폴드8과 스마트태그2 사이에 UWB 세션을 수립하고 거리값을 읽는 최소 PoC를 구현합니다.

성공 조건:

- 실제 스마트태그2 인식
- UWB Ranging Session 생성
- 실시간 거리값 출력
- 실제 이동 시 거리값 변화 확인

삼성 인증 또는 프로토콜 문제로 실패하는 경우 원인과 필요한 기술 작업을 분석합니다.

### Phase 2 — 백그라운드 검증

화면을 끄거나 다른 앱으로 전환해도 거리 측정 이벤트가 수신되는지 테스트합니다.

성공 조건:

- Foreground Service 실행
- 화면 잠금 상태에서 실제 거리값 수신
- 임계거리 이탈 이벤트 발생
- 장시간 동작 및 재연결 검증

이 단계가 실패하면 실사용 자동화를 구현할 수 있다고 판단하지 않습니다.

### Phase 3 — 앱 완성

Phase 1과 2가 성공하면 다음을 구현합니다.

- 태그 선택
- 실시간 거리 UI
- 임계거리 슬라이더
- 모니터링 상태 관리
- 설정 저장
- 자동화 이벤트 엔진

### Phase 4 — 자동화 연동

- Tasker 이벤트 연동
- 알림
- Webhook
- 이벤트 로그
- 배터리 최적화
- 오류 복구 및 안정성 검증

## 8. 에이전트 수행 지침

실제 코드를 작성하고 실행 가능한 프로젝트를 완성하는 것이 목표입니다.

기술적 세부사항은 현재 코드베이스, 최신 Android API 및 실제 스마트태그2 프로토콜에 맞춰 자율적으로 결정하세요.

단, 다음 순서를 반드시 지키세요.

**스마트태그2 UWB 연결 가능성 검증 → 백그라운드 거리 측정 검증 → 앱 UI 구현 → 자동화 연동.**

첫 두 단계가 검증되기 전에는 전체 기능이 완성됐다고 보고하지 마세요.

사용자가 실기기 테스트를 수행해야 하는 경우 테스트 가능한 APK와 구체적인 검증 절차를 제공하고, 실제 결과가 확인되지 않은 항목은 미검증으로 표시하세요.

최종 목표는 **화면이 꺼진 상태에서도 스마트태그2의 실제 UWB 거리를 측정하여 설정한 거리 이상 멀어졌을 때 Android 자동화를 트리거하는 앱**입니다.

## 후속 사용자 요청 (2026-11-07)

- 재부팅 후 첫 잠금 해제 시 이전 설정과 모니터링 ON/OFF 상태로 자동 추적 재개.
- 설정에서 상태표시줄의 추적 알림 표시를 제어.
- 이탈 임계거리 최대 10m. 원문 범위와 다르면 이 후속 요청을 우선 적용.

- 갱신 주기를 설정에서 바꿀 수 있게 한다. 기본값은 차량 접근·이탈 시 잠금/해제 자동화를 위해 기존 동작을 유지한다.
