# 차량 블루투스 모드와 이탈 신호

2026-11-08 작업의 정리 문서다. 사용자가 보고한 문제, 원인 판단, 구현한 동작과 규칙, 값, 기기에서 확인한 것과 못 한 것, 남은 위험을 한곳에 모았다. 구조는 [ARCHITECTURE.md](ARCHITECTURE.md), 현재 상태와 다음 작업은 [HANDOFF.md](HANDOFF.md), 관측 기록은 [DEVICE_TESTS.md](DEVICE_TESTS.md)에 있다. 이 문서의 시간 값은 모두 **첫 값이며 실주행으로 검증하지 않았다**.

단위 테스트 115개, 기기 계측 3개, Lint 오류 0 / 경고 1(monochrome 아이콘).

## 2. 배경과 원인 분석

사용자 보고(2026-11-08): ① 몇 시간 운전하면 SmartTag 배터리가 많이 줄어 있다. ② 차 안에서는 인식이 좋지만 내려서 멀어져도 자동으로 안 잠긴다. 확인하면 연결이 끊겨 있고 문을 닫는 순간 딱 끊기는 것 같다. 앞유리 쪽에 둬도 같다.

|증상|원인 판단|
|---|---|
|잠기지 않음|문이 닫히면 전파가 막혀 마지막 거리는 가까운 값에서 멈춘다. 거리 엔진은 실제 거리만 받으므로 이탈이 나올 수 없다. `TAG_DISCONNECTED`는 120초 뒤에만 나가고 `SmartThingsSwitch.stateFor`는 이를 스위치에 매핑하지 않았다. 스위치가 꺼질 길이 없었다|
|서비스가 멈췄을 수 있음|연결 상태 콜백의 status 8(링크 감독 타임아웃)을 ATT ‘권한 부족’ 8과 같은 영구 오류로 분류했다. 인증·MTU·활성화 중에 태그가 닿지 않게 되면 재시도 없이 서비스가 종료될 수 있었다. 실제로 탔는지는 저널이 없어 확인하지 못했다|
|배터리|연결된 동안 태그가 UWB를 240ms 간격으로 계속 켠다. 가만히 있는 운전 시간도 같다. **추정이며 측정하지 않았다**|

## 3. 동작

### 3.1 모드

설정의 차량 기기와 ‘차량 블루투스가 끊기면 추적 시작’이 모두 있을 때만 차량 모드이고, 아니면 기존 연속 추적이다. 차량 모드의 서비스는 계속 떠 있지만(FGS `connectedDevice`) 태그에는 접근하지 않고 차량 연결 상태만 본다.

차량 연결 여부(`CarLink`)는 세 신호의 OR이다: ACL 연결, A2DP, 핸즈프리(HFP). ACL이 끊기면 두 프로파일도 끊긴 것으로 본다. 차가 따로 갖는 Low Energy 링크(디지털 키 등)는 무시한다. 수신기는 반드시 `RECEIVER_EXPORTED`로 등록한다(§11). 시작할 때는 두 프로파일의 연결 기기 목록으로 현재 상태를 읽는다.

### 3.2 단계

|단계|의미|태그|스위치|
|---|---|---|---|
|`CAR_CONNECTED`|차량이 연결돼 있다|접근 안 함(UWB 없음)|켜짐 신호를 한 번 보내고 이탈 래치를 지운다|
|`WAITING`|차량 없이 시작했다. 이탈이 아니다|접근 안 함|건드리지 않음|
|`TRACKING`|차량이 연결됐다가 끊겼다(3초 확인). 추적 창 하나가 열려 있다|검색·인증·UWB|§4 규칙|
|`AWAY`|이탈이 확정돼 창이 닫혔다|접근 안 함|이탈 신호는 이미 보냄|

전이: 차량 연결 → 항상 `CAR_CONNECTED`(창이 있으면 취소). 차량 끊김이 3초 뒤에도 유지 → `CAR_CONNECTED`에서 `TRACKING`. `UNKNOWN`에서는 `WAITING`(재시작 복구 제외). 이탈 확정 → `TRACKING`에서 `AWAY`. 창이 결정 없이 끝나면(영구 오류 등) 안전 쪽으로 이탈 처리하고 서비스는 유지한다(§4.1).

3초 확인(`DISCONNECT_CONFIRM_MILLIS`): 오디오·핸즈프리가 따로 끊기는 순간적인 흔들림이 창을 열지 않게 한다. 모든 차량 신호는 신호 값이 아니라 **현재 상태**로 판정한다.

### 3.3 서비스 재시작 복구

OS 종료·충돌·업데이트·재부팅으로 서비스가 다시 뜨면 그 사이 차량이 끊겼을 수 있다. 단계와 시각을 저장해(`car_phase`, `car_phase_at`) 판단한다. 저장은 단계가 바뀔 때와 `CAR_CONNECTED`/`TRACKING`인 동안 1분마다 한다.

|재시작 때 저장된 값|지금 차량|결과|
|---|---|---|
|`CAR_CONNECTED`·`TRACKING`, 15분 이내|연결 안 됨|놓친 이탈. 추적 창을 연다(기준 시각은 지금)|
|같음|연결됨|대기|
|`AWAY`(나이 무관)|무엇이든|이탈 상태로 시작, 차량이 연결될 때까지 쉼|
|오래됐거나 없음·알 수 없는 값|연결 안 됨|판단 안 함, 대기(주차 뒤 재부팅이 이탈 신호를 내지 않게)|

사용자 중지, 차량 모드 끔, 차량 기기 변경은 저장을 지운다. 충돌·OS 종료·업데이트만 저장을 이어받는다.

## 4. 이탈 판단과 신호

### 4.1 판단 규칙

|상황|연속 모드|차량 모드(추적 창)|
|---|---|---|
|실제 거리가 임계를 지속 시간 넘음|`TAG_DISTANCE_EXCEEDED`, 스위치 이탈 신호|같음. 창을 닫음|
|가깝게 측정되던 태그가 끊김|마지막 거리 뒤 **30초**, 링크 손실 outage일 때|**8초**(`SEEN_THEN_LOST_MILLIS`)|
|창이 열린 뒤 한 번도 측정 못 함|판단 안 함|**60초**(`NEVER_MEASURED_MILLIS`). 실패 종류(광고 없음, 147, 133)와 무관. 폰 알림|
|창이 영구 오류로 결정 없이 끝남|서비스 종료(기존)|이탈 처리(안전 쪽). 한 번도 측정 못 했다면 알림도. 서비스는 유지|
|사용자가 Bluetooth를 끔|제외|제외(8초·60초 규칙)|

- 거리 이벤트(Tasker·Webhook·알림의 `TAG_DISTANCE_EXCEEDED`/`TAG_RETURNED`)는 **실제 UWB 거리로만** 만든다. 연결 소실 규칙은 SmartThings 스위치에만 작용한다. AGENTS.md의 ‘연결 중단으로 이탈을 만들지 않는다’는 이 예외만 허용한다.
- 차량 연결이 끊긴 순간이 ‘가까웠다’의 기준이다. 시작 때 차량이 없었다면 `WAITING`이라 이 규칙들이 작동하지 않는다.
- `TAG_DISCONNECTED`는 여전히 120초 뒤에만 나가며 차량 모드 창은 그 전에 닫힌다.
- 설정 ‘신호가 끊기면 멀어진 것으로 보고 끄기’(기본 ON)를 끄면 위의 연결 소실·8초·60초 규칙은 스위치 신호 없이 창만 닫는다.
- 판단은 `PresencePolicy`, `DepartureJudge`(순수, 시간선 테스트), 서비스의 1초 ticker가 한다.

### 4.2 켰다 끄기

이탈이 확정되면 `pulse`: 켜기 → 1.5초(`SwitchPulse.GAP_MILLIS`) → 끄기를 **한 요청**이 맡는다. 이미 꺼진 스위치에 끄기만 보내면 SmartThings에서 상태가 바뀌지 않아 ‘꺼지면’ 자동화가 다시 실행되지 않기 때문이다(11-07 시험에서 이미 꺼진 스위치에 끄기를 보내도 SmartThings의 상태·시각이 그대로였다). 한 요청이라 새 요청이 대기 중인 켜기를 지우지 못한다. 각 단계는 30초 만료·최신 요청·직렬화 검사를 거치고, 켜기가 실패하면 끄기를 보내지 않고 켜기부터 재시도한다.

- 시작 때 상태 맞추기(`on`/`off`)와 차량 재연결(`on`)은 펄스가 아니다.
- 설정 ‘이탈 때 켰다 끄기’(기본 ON)를 끄면 끄기만 보낸다.
- **‘켜지면’ 조건의 자동화가 있으면 이탈마다 한 번 실행된다.** 잠금 자동화는 ‘꺼지면’만 쓴다.
- 오프라인이면 기존 30초 만료로 신호가 버려진다(기존 정책).

### 4.3 연결 소실 분류

`GATT_CONNECTION_STATUS_8`(연결 상태 콜백의 status 8)은 링크 감독 타임아웃이라 재시도 가능한 링크 손실이다. ATT 쓰기·디스크립터·MTU·탐색의 8은 ‘권한 부족’이라 계속 영구 오류다.

## 5. 태그가 UWB를 시작하지 못할 때

소유자 인증까지 되는데 UWB가 안 되는 경우다(11-07 17시대 ACTIVATE `GATT_WRITE_STATUS_133` 반복, 11-08 07:13~07:25). 사용자가 ‘태그 배터리가 없을 때 그렇게 나온다’고 전했으나 **확정하지 못했다**.

- **감지**: 한 연결에서 인증 성공 뒤 거리를 한 번도 못 받고 `FailurePolicy.isUwbRefused`(GATT 쓰기 상태 오류, 쓰기 재시도 소진, `UWB_STOPPED_*`, `UWB_OPEN_FAILED_*`, `UWB_CLOSED_*`)로 끝나면 연속 거부로 센다. 거리를 받으면 0으로 돌아간다. `NO_UWB_REPORTS_20S`·`UWB_REPORTS_STALE_20S`는 세지 않는다(닫힌 문도 같은 증상).
- **대응**: 연속 2회면 저널 `TAG_UWB_UNAVAILABLE`과 폰 알림을 한 번 낸다. 재시도 간격을 5분 이상으로 늘린다(실패한 활성화도 약한 배터리를 쓴다). 차량 창은 60초 규칙이 적용되고 알림 문구만 UWB 거부 쪽이다.
- **11-08 조사 결과**(`test-results/uwb-no-response-episode.txt`): 폰 UWB 칩 로그상 세션은 열리고 모든 라운드가 돌았지만 태그의 응답이 없었다(`RangingStatus=33`, 10초 뒤 중지). 600ms로 3번 실패했으나 같은 자리에서 240ms는 성공했고, 이어서 600ms도 성공(A-B-A)했다. **갱신 주기는 원인이 아니다.** SmartThings가 파싱한 태그 광고의 `batteryLevel`은 06:48~07:14 내내 3이라 배터리 부족을 가리키지 않는다(3이 최상위라는 해석은 uTag 문서 기준, 미확인). 6~12분 뒤 저절로 풀렸다. 같은 시간대에 모의 차량으로 쓴 이어폰의 연결·해제와 LE 오디오 링크 흔들림이 있었으나 인과는 확인하지 못했다.
- **배터리 잔량은 읽을 수 없다.** 삼성 클라우드 태그 기록과 공개 API 상태에는 `battery` 기능 이름만 있고 값이 없다. 그래서 미리 경고하지 못하고 실패 신호로만 안내한다.
- 알림 문구가 ‘배터리 부족일 수 있다’로 기울어 있어 배터리가 정상으로 보이는 11-08 사례와 맞지 않는다. 중립 문구로 바꾸는 것이 후속 후보다.
- 미구현 후보: UWB를 포기하고 인증된 BLE 연결을 유지하다가 연결이 끊기면 이탈로 보는 대체 모드(거리 환산 없음).

## 6. 배터리

- 차량 모드: 차량이 연결된 동안과 이탈 뒤에는 태그를 쓰지 않는다. 가장 큰 효과를 기대하는 변경이다.
- 기본 UWB 갱신 600ms(`TrackingRate.DEFAULT`). 저장된 선택은 덮어쓰지 않는다.
- 첫 실제 거리 뒤 BLE 연결 우선순위 LOW_POWER 요청(`GATT_LOW_POWER accepted=true`를 기기에서 확인).
- **모두 태그·폰 배터리 절감량을 측정하지 않았다.** 지금까지의 시험은 USB 충전 중이었다.

## 8. 설정과 개발용 명령

설정 화면: ‘차량 블루투스 연동’(기기 선택·토글), SmartThings의 ‘이탈 때 켰다 끄기’·‘신호가 끊기면 멀어진 것으로 보고 끄기’·‘켰다 끄기 시험’. 차량 모드·추적 주기·차량 기기는 모니터링을 멈춘 상태에서 바꾼다.

화면을 넘겨 누르지 말고 adb 명령을 쓴다. `DebugCommandReceiver`는 `android.permission.DUMP`로 보호돼 shell만 보낼 수 있다. 자격 증명·토큰·키·SmartThings 기기 ID는 다루지 않고 저널 `DEBUG_COMMAND`에는 설정 이름만 남긴다.

```sh
adb shell am broadcast -n dev.uwbpulse.monitor/.debug.DebugCommandReceiver \
  --es tracking_rate SAVER --es car_device <등록된 기기 이름> \
  --ez car_mode true --ez smartthings true --ez pulse true --ez off_on_link_loss true \
  --es monitor start
```

`tracking_rate`는 FAST·NORMAL·SAVER, `monitor`는 start·stop이다. `monitor start`는 앱이 포그라운드일 때 확인했다.

저널 진단 줄: `CAR_LINK`(출처 acl/a2dp/hfp/seed와 상태), `CAR_LINK_OTHER`(다른 기기 알림 도착 확인, 주소·이름 없음), `CAR_PHASE`, `CAR_RESTORE`, `CAR_TRACKING_STOPPED`, `PRESENCE_LINK_LOST`/`PRESENCE_RESTORED`, `TAG_UWB_UNAVAILABLE`, `TICK_DELAYED`(타이머가 5초 넘게 늦음), `DEBUG_COMMAND`.

### 9.2 단위 테스트로만 확인

켰다 끄기 순서·실패 처리, 8초·60초·30초 시간선, 놓친 이탈 되살림과 15분 경계, `AWAY` 복원, 차량 신호 합성(`CarLink`)과 단계 전이, status 8 분류, UWB 거부 분류와 재시도 간격, 연결 소실 후 복귀.

### 9.3 확인하지 못함

- **실제 차량**: 차량 블루투스가 시동·문·거리에 따라 언제 끊기는지, ACL·프로파일 알림 수신, 이탈 확정 뒤 종료, 문 닫힘 때의 8초·60초·30초 규칙.
- 이어폰을 다시 연결했을 때 추적 창이 취소되고 스위치가 켜지는 경로, 차량이 연결된 채 서비스가 죽었다가 끊긴 채 되살아나는 경로, 재부팅 뒤 복구.
- 켰다 끄기의 실제 SmartThings 반응과 사용자의 잠금 자동화(유무도 모름). 스위치를 켰다 끄기 때문에 임의로 시험하지 않았다.
- 비충전·장시간 동작, 태그·폰 배터리 절감.
- 화면이 꺼진 동안의 타이머 지연(`TICK_DELAYED`로 수집 필요).

## 10. 알려진 위험

- **차 안 오탐**: 태그를 측정하다가 UWB·연결이 8초 넘게 흔들리면(재연결에 6~15초) 앉아 있어도 잠긴다. 태그가 안 맞거나 UWB가 응답하지 않으면 차량이 끊긴 60초 뒤 차 안에서도 잠긴다.
- **그날 차량 블루투스가 연결되지 않으면** 잠금이 없다. 연속 모드는 영향을 받지 않는다.
- **멀어진 뒤에야 끊기는 차**는 이미 태그 신호가 막혀 있어 잠금이 약 63초 뒤다.
- **화면이 꺼져 CPU가 잠들면** 코루틴 타이머가 멈춰 8초·60초가 늦을 수 있다. AGENTS.md는 wake lock을 쓰지 않는다고 못 박아 두었다.
- **오프라인이면** 30초 만료로 잠금 신호가 버려진다.
- 켜짐 조건 자동화가 있으면 켰다 끄기가 이탈마다 그것을 한 번 실행한다.
- 차량 모드에서는 차량이 연결된 동안 거리를 재지 않으므로 Tasker·Webhook의 `TAG_RETURNED`가 만들어지지 않는다(차량 재연결은 스위치만 켠다).
