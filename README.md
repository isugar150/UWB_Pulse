# UWB Pulse

갤럭시 **SmartTag2의 실제 UWB 거리**를 폰에서 계속 재다가, 내가 정한 거리(예: 5m)보다 멀어지면 **"이탈"**, 다시 가까워지면 **"복귀"** 신호를 보내는 안드로이드 앱입니다. 이 신호로 알림을 받거나, Tasker·웹훅·SmartThings 자동화(예: 차량 문 잠금)를 실행할 수 있습니다.

> English: An Android app that reads the real UWB distance to a Galaxy SmartTag2 and emits "left" / "returned" events when you cross a distance you choose. Events can drive notifications, Tasker, an HTTPS webhook, or a SmartThings virtual switch. No server of your own is needed. Unofficial, GPL-3.0-only. The guide below is in Korean.

```
SmartTag2 ──UWB──▶ 내 폰(UWB Pulse) ──이탈/복귀 이벤트──▶ 알림 · Tasker · 웹훅 · SmartThings 가상 스위치 → 자동화
```

- **서버가 필요 없습니다.** 앱이 폰에서 직접 태그와 통신하고, SmartThings도 앱이 직접 호출합니다.
- **임의 값을 만들지 않습니다.** 실제 UWB 측정값만 거리로 쓰고, 신호가 끊겼다는 이유로 이탈을 만들지 않습니다.
- **비공식 앱입니다.** 삼성과 관련이 없고, 삼성 계정·SmartThings의 비공식 호환 방식을 씁니다. [안전과 한계](#안전과-한계)를 꼭 읽어 주세요.

## 1. 준비물

|필요한 것|설명|
|---|---|
|**UWB를 지원하는 갤럭시 폰**|개발과 시험은 Galaxy Z Fold8(SM-F971N, Android 17, One UI 9) 한 대로 했습니다. 다른 기기·펌웨어는 확인하지 못했습니다|
|**SmartTag2**|이미 **SmartThings(Find)에 내 삼성 계정으로 등록된** UWB 태그. 이 앱은 태그를 초기화하거나 다시 등록하지 않습니다|
|**삼성 계정**|태그를 등록한 그 계정|
|**PC**|앱을 직접 빌드해서 폰에 설치할 때 필요합니다. 이 저장소에는 설치용 APK가 들어 있지 않습니다|
|**USB 케이블**|PC와 폰 연결용|

시작하기 전에 폰에서 **Bluetooth와 UWB를 켜 두세요.**

## 2. 앱 설치하기

### 2-1. 폰 준비 (한 번만)

1. **설정 → 휴대전화 정보 → 소프트웨어 정보**에서 **빌드번호**를 7번 눌러 개발자 옵션을 켭니다.
2. **설정 → 개발자 옵션**에서 **USB 디버깅**을 켭니다.
3. 폰을 PC에 USB로 연결하고, 폰에 뜨는 "USB 디버깅을 허용하시겠습니까?"에서 **허용**합니다.

### 2-2. PC 준비 (한 번만)

- **Android Studio**를 설치합니다. 처음 실행할 때 Android SDK도 같이 설치됩니다. 이 프로젝트는 **Android SDK Platform 37**과 **Build Tools 36.0.0**이 필요합니다(Android Studio의 SDK Manager에서 설치).
- **JDK 25**가 필요합니다. 설정에 JDK 25를 Gradle이 내려받도록 적혀 있지만 환경에 따라 실패할 수 있으니, 빌드 중 JDK 오류가 나면 JDK 25를 직접 설치하세요.
- **Git**이 필요합니다.
- `adb`(폰과 통신하는 도구)는 Android SDK의 `platform-tools`에 있습니다. 터미널에서 `adb version`이 나오지 않으면 그 폴더를 PATH에 추가하세요.

### 2-3. 받아서 빌드하고 설치하기

터미널(Windows는 PowerShell)에서 차례로 실행합니다.

```sh
git clone https://github.com/isugar150/UWB_Pulse.git
cd UWB_Pulse
```

Android SDK 위치를 알려 줍니다. Android Studio로 이 폴더를 한 번 열면 `local.properties`가 자동으로 만들어집니다. 직접 만들려면 `local.properties` 파일에 SDK 경로를 한 줄로 적습니다(macOS 예시).

```properties
sdk.dir=/Users/내이름/Library/Android/sdk
```

빌드합니다(Windows PowerShell에서는 `./gradlew` 대신 `.\gradlew.bat`). 처음에는 도구를 내려받느라 몇 분 걸립니다.

```sh
./gradlew :app:assembleDebug
```

폰이 연결됐는지 확인하고 설치합니다.

```sh
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`adb devices`에 폰이 `device`로 보여야 합니다. `unauthorized`면 폰의 USB 디버깅 허용 창을 확인하세요.

> **Android Studio로 하는 방법:** 폴더를 열고(Open), 위쪽에서 연결된 폰을 고른 뒤 ▶ Run을 누르면 빌드와 설치가 한 번에 됩니다.

> **앱을 지우지 마세요.** 앱 데이터와 암호화 키를 유지하려면 같은 서명의 APK로 `adb install -r`(덮어쓰기)로 업데이트하세요. 지우면 삼성 계정을 다시 연결해야 합니다.

## 3. 처음 실행하기

1. 폰에서 **UWB Pulse**를 엽니다.
2. **삼성 계정으로 내 태그 연결**을 누릅니다. 삼성 로그인 화면이 열리면 **본인이 직접** 로그인하고 동의합니다. 비밀번호는 삼성 화면에서만 입력하며 이 앱은 받지 않습니다.
3. 로그인이 끝난 뒤 "어떤 앱으로 열까요?" 같은 선택 창이 나오면 **UWB Pulse**를 고릅니다.
4. 화면 위쪽 목록에서 **내 태그**를 선택합니다. 태그가 하나뿐이면 자동으로 선택됩니다. 목록이 비어 있으면 [문제가 생기면](#6-문제가-생기면)을 보세요.
5. **모니터링 시작**을 누르고 요청되는 권한을 **허용**합니다(근처 기기, UWB, 알림).
6. 잠시 뒤 **실제 UWB 수신** 카드에 거리(예: `0.22 m`)와 "측정 신뢰도: 높음"이 나오면 성공입니다. 태그를 들고 걸어 보며 숫자가 바뀌는지 확인하세요.
7. 쓰지 않을 때는 **모니터링 중지**를 누릅니다. 중지하면 재부팅 후에도 자동으로 시작하지 않습니다.

처음 시작할 때, 특히 중지 직후 다시 시작하면 첫 거리가 나오기까지 **20~70초** 걸리기도 했습니다. 기다려 보세요.

### 꼭 해 두면 좋은 폰 설정

- **배터리**: 앱 안의 **설정 → 배터리 최적화 설정**으로 이동해 이 앱을 제한하지 않도록 두세요. 삼성의 "절전"·"잠자는 앱" 목록에 들어가 있으면 빼 주세요.
- **알림**: 추적 중에는 상태 알림이 하나 떠 있습니다. 숨기고 싶으면 **설정 → 추적 중 알림 표시**에서 시스템 알림 채널을 끄면 됩니다(추적은 계속됩니다).
- **재부팅**: 폰을 재부팅하면 **첫 잠금 해제 뒤** 자동으로 추적을 다시 시작합니다(설정에서 끌 수 있습니다).

## 4. 거리와 주기 설정

메인 화면과 **설정**에서 바꿉니다. 처음 쓰는 분은 **기본값 그대로 써도 됩니다.**

|항목|기본값|설명|
|---|---|---|
|이탈 임계거리|**5 m**|슬라이더로 1~10m, 0.5m 단위. 이 거리보다 멀리 있는 상태가 이탈 지속 시간 동안 이어지면 이탈|
|복귀 거리|**4 m**|이 거리 안으로 들어오면 복귀. 임계거리보다 짧게 두어야 경계에서 이탈·복귀가 반복되지 않습니다|
|이탈 지속 시간|3초|순간적으로 튄 값 때문에 이탈이 나지 않도록 기다리는 시간|
|UWB 갱신 주기|기본 **240 ms**|빠름 120 ms / 기본 240 ms / 절전 600 ms. 차량 접근·이탈 용도로 기본을 권장합니다. **모니터링을 멈춘 상태에서** 바꾸세요|
|이탈 후 태그 재탐색 간격(최대)|1분|연결이 끊긴 뒤 태그를 다시 찾는 최대 간격(10초~5분)|

먼저 **짧은 거리(예: 임계 1.5m, 복귀 1.0m)로 시험**해 보면 이벤트가 나오는지 쉽게 볼 수 있습니다. 실제로 쓸 때는 되돌리세요.

더 정확한 동작 규칙은 [상세 동작 안내](docs/REFERENCE.md)에 있습니다.

## 5. 이탈·복귀를 자동화에 연결하기

앱은 이탈·복귀를 다음 이벤트로 만듭니다. **연결 방법은 하나만 골라도 됩니다.**

|이벤트|뜻|
|---|---|
|`TAG_DISTANCE_EXCEEDED`|이탈|
|`TAG_RETURNED`|복귀|
|`TAG_DISCONNECTED`|태그와 2분 넘게 연결이 끊김|
|`UWB_MONITORING_ERROR`|복구할 수 없는 오류(로그인·권한 등)|

짧은 연결 끊김은 이벤트로 내보내지 않습니다. 설정의 **이벤트 알림**에서 이벤트별 알림을 켜고 끌 수 있고, 알림만 써도 이탈·복귀를 눈으로 확인할 수 있습니다.

### 방법 A. SmartThings 가상 스위치 (차량 잠금 등)

**이탈하면 SmartThings의 가상 스위치가 켜지고, 복귀하면 꺼집니다.** SmartThings 자동화에서 "그 스위치가 켜지면"을 조건으로 쓰면 됩니다. 내 서버는 필요 없고, 폰이 잠겨 있어도 동작하는 경로입니다. 삼성 로그인 토큰을 SmartThings 공개 API에 쓰는 **비공식** 방식이라는 점을 [안전과 한계](#안전과-한계)에서 확인하세요.

**① 가상 스위치 만들기 (PC에서 한 번)**

1. [SmartThings CLI](https://github.com/SmartThingsCommunity/smartthings-cli/releases)를 설치합니다(macOS는 `brew install smartthingscommunity/smartthings/smartthings`). 처음 명령을 실행하면 로그인 안내가 나오니 삼성 계정으로 로그인합니다.
2. SmartThings 앱에서 가상 스위치를 둘 **방**을 정해 둡니다. 그리고 위치 ID와 방 ID를 확인합니다.

   ```sh
   smartthings locations
   smartthings rooms
   ```

3. `virtual-switch.json` 파일을 만듭니다. `<방 ID>`와 `<위치 ID>`만 바꾸세요.

   ```json
   {"name":"UWB_Pulse","roomId":"<방 ID>","owner":{"ownerType":"LOCATION","ownerId":"<위치 ID>"},"deviceProfile":{"components":[{"id":"main","capabilities":[{"id":"switch","version":1}],"categories":[{"name":"Switch"}]}]}}
   ```

4. 만듭니다.

   ```sh
   smartthings virtualdevices:create -j -i virtual-switch.json
   ```

   출력에서 **`deviceId`** 값을 복사해 둡니다. SmartThings 앱의 기기 목록에 `UWB_Pulse`가 보여야 합니다.

**② 앱에 연결하기 (폰에서)**

1. UWB Pulse → **설정 → SmartThings 가상 스위치**로 갑니다.
2. **가상 스위치 기기 ID**에 복사한 `deviceId`를 붙여 넣고 **저장 및 연결**을 누릅니다. OAuth 항목은 **비워 두세요.**
3. **삼성 로그인 토큰으로 연결 시험 (읽기·쓰기)**을 누릅니다. `읽기 200 · 쓰기 200`이 나오면 통신이 됩니다.
4. **스위치 끄기 시험**을 눌러 SmartThings 앱의 `UWB_Pulse`가 꺼짐인지 봅니다. (**켜기 시험은 연결한 자동화를 실제로 실행**하니, 자동화를 만든 뒤에는 조심하세요.)
5. **이탈 시 스위치 켜기 · 복귀 시 끄기**를 켭니다.

**③ SmartThings 자동화 만들기 (SmartThings 앱에서)**

1. **자동화 → 만들기**로 갑니다.
2. **만약**: 기기 상태 → `UWB_Pulse` → **켜짐**.
3. **그러면**: 실행할 동작(예: 차량 문 잠금 루틴).
4. **처음에는 알림 보내기 같은 무해한 동작으로 시험**하고, 잘 되는 것을 본 다음에 실제 동작으로 바꾸세요.

이벤트는 발생 후 **30초부터 폐기**합니다. 인터넷이 늦게 복구돼도 오래된 차량 자동화 신호를 보내지 않습니다. 새 상태가 이전 대기를 교체하며 전송을 직렬화합니다. 이미 서버로 보낸 동작은 취소할 수 없습니다.

전송 결과는 앱의 **진단 보고서**(또는 로그)에 `ST_SWITCH_RESULT ... httpStatus=200`으로 남습니다. 200이 아니면 [문제가 생기면](#6-문제가-생기면)을 보세요. 자세한 설명과 확인 기록은 [SmartThings 연결 안내](docs/SMARTTHINGS_SETUP.md)에 있습니다.

### 방법 B. Tasker

1. 앱 설정에서 Tasker 이벤트 플러그인을 켭니다.
2. Tasker → 프로필 → 이벤트 → 플러그인 → **UWB Pulse 이벤트**를 고르고 ALL 또는 원하는 이벤트를 선택합니다.
3. 변수 `%uwb_event`, `%uwb_distance`, `%uwb_threshold`, `%uwb_timestamp`, `%uwb_tag`를 쓸 수 있습니다.

이 연결은 코드로 구현했지만 시험 기기에 Tasker 앱이 없어 **실제 Tasker 동작은 확인하지 못했습니다.**

### 방법 C. HTTPS 웹훅

내 서버나 자동화 서비스(HTTPS 주소)로 이벤트를 보냅니다. **설정 → HTTPS Webhook**에 주소와 (필요하면) 인증 토큰을 저장하고 전송을 켭니다. 토큰은 암호화해 저장하고 화면에 다시 보여 주지 않습니다. 받는 쪽 서버는 제공하지 않으며, 외부 서버에 도착하는 것까지는 확인하지 못했습니다. 형식과 재시도 규칙은 [상세 동작 안내](docs/REFERENCE.md#https-webhook-선택)에 있습니다.

## 6. 문제가 생기면

|증상|확인할 것|
|---|---|
|태그 목록이 비어 있다|태그가 **UWB를 지원하는 SmartTag2**이고 **같은 삼성 계정의 SmartThings에 등록**돼 있나요? 설정의 **내 태그 새로고침**을 눌러 보세요|
|로그인 뒤 앱으로 돌아오지 않는다|"어떤 앱으로 열까요?"에서 **UWB Pulse**를 선택했는지 확인하고, 다시 **삼성 계정으로 내 태그 연결**을 누르세요|
|거리가 `— m`로 나온다|태그가 너무 멀거나 Bluetooth/UWB가 꺼져 있을 수 있습니다. 같은 태그를 다른 앱의 **가까이 찾기**로 동시에 쓰면 충돌할 수 있으니 그 화면을 닫으세요|
|시작하고 한참 지나서야 거리가 나온다|중지 직후 재시작이면 20~70초 걸릴 수 있습니다. 계속 안 되면 모니터링을 중지했다가 다시 시작하세요|
|화면을 끄거나 시간이 지나면 멈춘다|**배터리 최적화 설정**에서 제한을 풀고, 삼성 절전·잠자는 앱 목록에서 빼세요. '강제 중지'를 하면 앱을 다시 열어야 합니다|
|알림이 오지 않는다|알림 권한과 설정의 **이벤트 알림** 스위치를 확인하세요|
|SmartThings 시험이 `읽기 401` 또는 `403`이다|설정에서 **삼성 계정 연결**로 다시 로그인한 뒤 다시 시험하세요. 계속 막히면 삼성·SmartThings 쪽 정책 때문일 수 있습니다([안전과 한계](#안전과-한계))|
|SmartThings 스위치는 켜졌는데 자동화가 안 돈다|SmartThings 앱에서 자동화가 켜져 있고 조건이 `UWB_Pulse` **켜짐**인지 확인하세요|
|빌드가 JDK 오류로 실패한다|JDK 25를 설치하세요|
|빌드가 SDK 오류로 실패한다|`local.properties`의 `sdk.dir` 경로와 SDK Platform 37·Build Tools 36.0.0 설치 여부를 확인하세요|

문의나 버그 보고에는 앱의 **진단 보고서 내보내기**를 쓸 수 있습니다. 보고서에는 거리·시각·기기 빌드·오류 코드가 들어가고 토큰이나 태그 키는 들어가지 않게 만들었지만, **올리기 전에 한 번 훑어보세요.**

## 안전과 한계

- **비공식 앱입니다.** 삼성 계정 로그인과 태그 정보 조회는 공개된 프로토콜 연구(uTag 문서 등)를 바탕으로 한 호환 구현입니다. 삼성·SmartThings의 정책이나 펌웨어가 바뀌면 동작하지 않을 수 있습니다.
- **SmartThings에 삼성 로그인 토큰을 쓰는 것은 비공식 사용입니다.** 2026-11-07에는 통했지만 **며칠 뒤에도 통하는지는 확인하지 못했습니다.** 막히면 OAuth 앱 방식으로 바꿀 수 있게 코드가 남아 있습니다. 이 토큰은 내 SmartThings 계정의 기기를 제어할 수 있으므로 앱은 Android Keystore로 암호화해 보관합니다.
- **차량·도어락 자동화는 신중하게 쓰세요.** UWB 거리는 오차가 있고, 연결 끊김·배터리·OS 절전·인터넷 문제로 신호가 늦거나 가지 않을 수 있습니다. **문을 여는 자동화는 특히 위험할 수 있으니 처음에는 알림으로, 다음엔 잠그는 동작으로만 시험**하세요. 이 앱은 어떤 보장도 하지 않습니다(GPL-3.0의 무보증 조항).
- 전송 결과가 화면에 표시되지는 않습니다. SmartThings 호출이 실패해도 앱 화면에는 나오지 않고 진단 로그에만 남습니다. 처음 며칠은 로그에 `httpStatus=200`이 계속 남는지 보세요.
- 이 앱은 **태그를 초기화하거나 기존 삼성 등록을 지우지 않습니다.** 그런 작업은 하지 마세요.
- 한 번에 한 개의 태그만 모니터링합니다.

## 개인정보와 민감정보

- **앱은 내 서버를 쓰지 않습니다.** 인터넷은 삼성·SmartThings 서버(로그인, 태그 정보, 가상 스위치 호출)와 내가 지정한 웹훅 주소에만 씁니다.
- 삼성 계정 **비밀번호는 삼성 로그인 화면에서만** 입력합니다.
- 로그인 토큰·태그 키·SmartThings 기기 ID·웹훅 토큰은 **Android Keystore로 암호화한 앱 내부 저장소**에 보관하고, 백업·기기 간 전송 대상에서 제외합니다.
- 로그에는 키·토큰·전체 BLE 주소·클라우드 태그 ID를 기록하지 않습니다. 거리·시각·오류 코드·기기 빌드는 기록합니다.
- **내 SmartThings 기기 ID, 위치/방 ID, 토큰, 삼성 계정 정보를 이슈·README·커밋에 올리지 마세요.** 이 저장소의 문서에는 `<방 ID>` 같은 자리표시자만 있습니다.
- 저장소를 포크해서 개발한다면 `local.properties`, `*.vault`, `*.jks`/`*.keystore`, `.env`, APK·ZIP, `test-results/device-*.txt`는 `.gitignore`로 제외돼 있습니다. 새로 모은 기기 로그는 **비밀과 식별자를 점검한 뒤** 필요한 부분만 올리세요.

## 무엇을 확인했고 무엇을 확인하지 못했나

시험은 **한 대의 폰(SM-F971N, Android 17)과 SmartTag2 한 개**, Android Ranging(플랫폼) 방식으로 했고 대부분 USB 충전 상태였습니다. 자세한 기록과 원본 증거는 [실기기 시험 기록](docs/DEVICE_TESTS.md)에 있습니다.

**확인함**

- 삼성 계정 로그인, 내 태그 목록과 소유자 키 조회, 태그와의 상호 인증, 실제 UWB 거리 수신
- 앱을 닫거나 화면을 꺼도 추적 지속(약 15분 시험에서 화면 OFF 콜백 3,549개), 재부팅 후 첫 잠금 해제만으로 자동 재개
- 실제로 멀어졌다 돌아왔을 때 이탈·복귀 이벤트가 각각 한 번씩 발생
- 갱신 주기 120/240/600 ms가 실제 콜백 간격으로 반영됨
- 일시적인 재연결 실패가 외부 이벤트로 나가지 않음
- Bluetooth/UWB OFF·ON 및 프로세스 종료 후 앱을 열지 않아도 실제 거리 수신 재개(각 1회)
- SmartThings 가상 스위치: 앱이 서버 없이 직접 호출해 **이탈 시 켜짐, 복귀 시 꺼짐**(이벤트 후 0.1~0.2초에 전송, HTTP 200), 이전 빌드에서 오프라인 신호의 복구 후 전송 확인. 현재 빌드는 30초 만료 적용

**아직 확인하지 못함**

- 가상 스위치를 조건으로 한 **차량 잠금 자동화와 전체 지연**
- 삼성 로그인 토큰의 **장기 유효성**과 401 갱신 경로
- 600 ms 절전 주기의 **실제 배터리 절감**(콜백 간격만 확인), 비충전·장시간 시험
- Tasker 앱 연동, 외부 웹훅 서버 도착
- 다른 폰·태그·Android 버전, AndroidX UWB 방식
